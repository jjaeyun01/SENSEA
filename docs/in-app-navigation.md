# SENSEA 앱 내부 안내 프로토타입

외부 Google Maps 앱으로 이동하지 않습니다. 건물 검색·주소 확인은 UW의 공개 지도 응답을 사용하고, 경로 계산은 서버가 Google Routes API에 요청합니다. 지도는 앱 내부 Google Maps SDK, 위치는 Expo Location, 음성 입력은 OS 음성 인식, 출력은 공통 TTS/화면 읽기·진동 모듈을 사용합니다.

## 현재 구현

1. 시작 멘트 → 영어 목적지 음성/텍스트 입력. 첫 권한 허용은 음성 버튼에서 진행합니다.
2. UW 건물 후보 선택 → 이름·도로명 주소를 읽고 `yes` 또는 확인 버튼으로 재확인합니다.
3. 사용 중 위치 권한 → 현재 위치 확인 → Google 도보 경로의 시간·거리 비교. 대안이 하나뿐이면 하나만 표시합니다.
4. 카메라 준비 안내 → 기존 이용 안내와 카메라 권한 → 사용 가능한 영상이 들어온 뒤 안내 시작 버튼이 활성화됩니다. 일반 객체 인식만으로 VPS 위치 정합을 주장하지 않습니다.
5. 앱 내부 Google 지도와 음성/진동. 순차적인 경로 끝점에 접근할 때 다음 단계 지시를 읽습니다. 위치 오차 반경까지 포함해 10m/3m 이내일 때만 해당 안내를 출력합니다. 일반 휴대폰 GPS로 3m 정확도를 얻지 못하면 다음 단계로 진행하지 않을 수 있습니다.
6. 위치가 5초 넘게 오래되거나 오차가 10m를 넘으면 회전 지시를 보류합니다. 카메라 중단·앱 백그라운드 전환 시 안내를 일시정지하고 자동 재개하지 않습니다.
7. 현재 단계 이후의 경로 선분에서 25m 이상 벗어난 정확한 GPS 값이 최소 3회, 1.5초 이상 지속되면 사용자를 정지시키고 현재 위치에서 Google 도보 경로를 다시 요청합니다. 재탐색 실패 또는 시간 초과 시 기존 안내를 일시정지합니다.
8. DeviceMotion은 위치를 새로 만들어내지 않고, 정지 상태에서 발생한 비현실적인 GPS 순간 이동을 거부하는 용도로만 사용합니다. `connectVerifiedVpsSource`에 등록된 공간맵 공급자의 결과 중 신뢰도 0.9 이상, 오차 10m 이하, 2초 이내이며 최근 GPS와 15m 이내인 좌표만 GPS와 제한적으로 결합할 수 있습니다.
9. 현장 조사된 출입구 좌표가 있으면 목표 지점을 해당 입구로 설정합니다. GPS 정확도와 조사 정확도를 모두 포함한 범위 안의 서로 다른 위치값이 3회 확인되어야 '검증된 출입구 좌표 근처'로 판정합니다. 이후에도 사용자가 직접 도착을 확인해야 합니다.
10. 출입구 자료가 없으면 대표 건물 좌표까지만 안내하고 '출입구가 검증되지 않음'을 알립니다.
11. 카메라의 안정된 사물 관측은 경로 멘트보다 먼저 출력할 수 있습니다. 큐는 짧게 유지하고 오래된 음성은 폐기합니다. 이는 충돌 위험 등급이나 회피 방향 판정이 아닙니다.

## 검증된 출입구 데이터

기본 `backend/data/entrances.json`은 의도적으로 비어 있습니다. 실제 현장 조사 없이
입구 좌표를 넣거나 `verified: true`로 표시하지 마세요. 조사된 값은 다음 형식으로
추가하며 `backend/data/entrances.example.json`도 참고할 수 있습니다.

```json
{
  "UW_MAP_BUILDING_ID": {
    "latitude": 43.000000,
    "longitude": -89.000000,
    "verified": true,
    "accuracy_m": 3,
    "surveyed_at": "2026-09-27T12:00:00-05:00",
    "description": "Field-surveyed public entrance"
  }
}
```

`accuracy_m`은 0보다 크고 10m 이하여야 한다. 필수 검증 정보가 하나라도 없거나
형식이 잘못되면 서버는 해당 값을 사용하지 않고 대표 건물 좌표로 되돌아간다.

## 환경 설정

[모바일 설정](../mobile/.env.example), [서버 설정](../backend/.env.example)을 참고합니다. 서버 Routes 키와 모바일 Maps SDK 키를 분리합니다. Google 결과를 다른 제공자의 지도 위에 표시하지 않습니다. 지도 밖 경로 카드에는 Google Maps 출처를 표시합니다.

백엔드는 `uvicorn app.main:app --host 0.0.0.0 --port 8000 --env-file .env`로 실행할 수 있습니다. `app.foundation:app`도 campus 엔드포인트를 제공합니다. 네이티브 앱은 `npm ci`, `npm run models:download`, `npm run ios -- --device` 또는 Android 개발 빌드로 실행합니다.

서버 공용 토큰은 해커톤 프로토타입용입니다. 공개 배포 전 사용자 인증, 서버 요청량 제한, Google 사용량 제한, 공개 개인정보처리방침·이용약관이 필요합니다.

## 기록

인식한 명령 텍스트·목적지 선택/확인·주요 버튼·화면 터치·안내 이벤트 종류를 기기 SQLite에 기록합니다. 시간과 이벤트를 최대 2,000개 보관하고 앱 사용 시 7일 초과 자료를 정리합니다. 원본 녹음·영상·GPS 궤적·Google 지시문을 저장하지 않습니다. 끄기 설정은 다음 실행에도 유지되고 별도 삭제 버튼이 있습니다. 모든 센서 이벤트를 보존하는 블랙박스나 사고 방지 보증은 아닙니다.

## 별도 구현·검증이 필요한 요구사항

- Siri/App Intents 및 Android Assistant의 전용 앱 실행 명령. 현재는 OS의 일반 앱 열기 기능을 사용합니다.
- 캠퍼스 공간맵과 현장 앵커를 사용하는 실제 VPS 공급자 연결. 현재 센서 융합은 검증된 VPS 결과를 받을 수 있지만, 일반 객체 탐지 결과를 VPS로 취급하지 않습니다.
- 안전 우선·평지 우선 경로: 검증된 경사·계단·공사·보차 분리 데이터를 확보해야 합니다.
- 장애물까지의 실제 거리, 계단 수/높이, 이동 속도, 충돌 위험, 안전한 회피 방향. 기존 객체 모델은 이를 출력하지 않습니다.
- AR 기반 휴대폰 파지 각도 검증과 출입문 자체의 시각적 확인. 현재 출입구 판정은 현장 조사 좌표에 대한 보수적 근접 판정입니다.
- 소음 측정과 보정된 dB, 소음에 따른 음량 조절, 기기별 방향 햅틱. 현재는 일반 진동 패턴을 사용합니다.
- 음성/터치 기록의 사용자 내보내기와 오류 후 복구.

## 검증

자동 검사: UW 검색 파싱·중복 제거·외부 서비스 실패, 주소/좌표 검증, Google 서버 요청 계약·인증·키 누락·경로 없음, 위치 신선도/오차와 단계 안내, 기존 카메라/버퍼 테스트, TypeScript 검사.

실제 UW 검색과 주소 응답은 확인했습니다. Google 유료 경로 API는 키가 없어 실제 요청하지 않았습니다. 실제 기기 STT/TTS/화면 읽기/진동, 지도 SDK 렌더링, GPS 지연·이탈·3m 도달, 새 네이티브 패키지 빌드는 별도로 검증해야 합니다. 혼자 보행하는 사용자의 안전을 검증한 시스템으로 취급하지 않습니다.
