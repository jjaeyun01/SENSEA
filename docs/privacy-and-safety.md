# 개인정보·안전 규칙 구현 기록

현재 카메라 시험판 v0.4와 백엔드 v0.3 기준입니다. 기능 구현 기록이며 실제 안전성·접근성 인증이나 법률 검토 결과가 아닙니다.

| README 12번 요구 | 코드에 반영한 내용 | 남은 확인 |
|---|---|---|
| 필요 시 권한·명확한 중지 | 첫 사용 안내, 사용 시 카메라 권한, 작동 상태, 중지·지우기, 안내/백그라운드에서 중지 | 권한 거절·철회와 앱 중단 실기기 시험 |
| 원본 비저장·키 분리 | 로컬 분석, 영상 업로드/파일 생성 없음, 서버 키 미포함 | OS·네이티브 모듈 동작 실기기 확인 |
| 소음 집계·만료 | 동의 true만 수신, 구간 단위 최대 1000개, TTL, 유휴 구간 주기 정리, 종료 시 삭제 | 실제 마이크, DB 어댑터와 DB 삭제 작업 |
| 안전 단정 방지 | 미인식을 빈 길로 표현하지 않음, 오래된/미래 결과 차단, navigation_safe=false, 서버 고불확실성 음성 문구 | 인식률·누락률·장면별 사용성 평가 |
| 검증된 보행 구간 | 검증 날짜 없는/만료된/미래 검증 구간 제외, 가상 경로 명시 | 실제 구간 조사와 재검토 담당자 |
| 당사자 참여 | 접근성 역할·레이블·초점·음성 충돌 방지와 시험 절차 | 시각장애인/저시력 사용자·접근성 전문가 검토 |

## 데이터 흐름

현재 APK: 카메라 → 작은 네이티브 프레임 → 기기 내 모델 → 최신 결과/음성. 사진·영상·분석 이력 파일을 만들지 않고 서버로 전송하지 않습니다. 앱 세션의 안내 확인 상태 역시 파일로 저장하지 않습니다. 사진/GPS/마이크 권한을 미리 묶어 요청하지 않습니다.

별도 서버 사진 모듈: 수신 서비스와 사진 전송 내용을 안내 → 명시적 동의 → 정지 확인 → 사진 → HTTPS 백엔드 → EXIF 제거·크기/품질 검사 → 구성된 외부 AI → 짧은 설명. 이 기능은 현재 APK 화면에는 연결하지 않았습니다. 동의가 없으면 클라이언트는 촬영/요청을 하지 않고 서버도 공급자를 호출하지 않습니다. 서버 수신까지 막으려면 클라이언트가 촬영 전에 동의를 확인해야 합니다.

캡처 어댑터는 자신이 만든 임시 사진의 삭제 콜백을 제공해야 합니다. 성공·실패·취소 시 호출하며 삭제 실패 시 추가 촬영을 막습니다. HTTP 요청이 끝나기 전에는 전송 중 파일을 삭제하지 않습니다. 취소가 무시되면 정리도 요청 종료까지 지연될 수 있습니다. 이미 전송된 데이터를 동의 철회로 회수할 수는 없습니다.

서버 응답은 캐시 금지이며 실행 예에서 접근 로그를 끕니다. multipart 임시 파일은 요청 종료 시 닫습니다. 외부 AI의 보관 정책, 운영 호스팅/프록시 로그, 디스크 스풀 정책은 배포 환경에서 별도 확인해야 합니다.

## 기한과 한계

- 소음 요약: 기본 1시간, 유휴 정리 기본 60초. TTL에 정리 주기와 실행 지연이 더해질 수 있습니다. 프로세스 종료 시 메모리 저장소를 비웁니다.
- 보행 검증: 기본 24시간. 시험용 재검토 규칙이며 그 시간 안의 도로 상태를 보장하지 않습니다. 현재는 실제 좌표 없는 가상 데이터만 사용합니다.
- 카메라 결과: 생성 시점부터 1초를 넘거나 시계가 뒤로 이동한 결과는 버립니다. 모델의 인식 지연·발열·메모리는 실기기 측정 전입니다.
- 강제 메모리 덮어쓰기나 OS/외부 서비스의 완전 삭제는 보장하지 않습니다. 특정 개인 식별자와 이동 기록을 수집하지 않아 익명 소음값을 개인별로 추적해 삭제하는 API는 만들지 않았습니다.

## 검증

백엔드 테스트는 외부 동의 거절, 사진 품질/EXIF 제거, 업로드 동시 처리 상한, 캐시 금지, 유휴 만료/종료 정리, 오래된 보행 검증 제외를 검사합니다. Node 테스트는 동의 철회, 임시 사진 정리, HTTPS 설정, 결과 만료, 버퍼 반환을 검사합니다. 네이티브 빌드는 Android의 실제 합쳐진 권한과 iPhone 권한 설명 키를 검사합니다. 테스트 픽셀은 직접 생성하며 회사 자료를 사용하지 않습니다.
