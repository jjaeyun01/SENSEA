# 보도 시설물·미국 교차로 인식 개발 방향

2026-09-27: 최초 방향 문서를 작성한 뒤, 사용자의 추가 구현 요청에 따라 **v0.4.7 Android 시험 기능**을 구현했습니다. 아래 후속 목표와 현장 평가 항목은 여전히 구분합니다.

## v0.4.7에 연결한 기능

- Google OWL-ViT를 고정된 29개 텍스트 질의와 384px 입력으로 변환한 INT8 ONNX 모델을 APK에 포함합니다. 가로등·쓰레기통·자전거 거치대/보관함·볼라드·화단·공사 시설물·계단·연석·나뭇가지 등은 **실제 모델이 출력하는 확장 후보**입니다. 새 이름만 기존 COCO 결과에 붙이는 방식이 아닙니다. 추가 학습 및 대상별 현장 정확도 평가는 하지 않았습니다.
- 카메라 RGBA 프레임을 긴 변 640px 이하로 한 장만 복사합니다. 600ms 간격보다 자주 시작하지 않고 처리 중인 입력은 버립니다. 기본 탐지는 기존 경로로 계속 실행합니다. 캡처 후 1초를 넘긴 확장 결과는 표시·발화하지 않으며 반복 지연/처리 정체 시 확장 분석을 중지합니다.
- 보행 신호 후보 상자 내부에 있는 ML Kit 숫자·문자만 사용합니다. 같은 신호의 연속 관찰 두 번으로 숫자/기호를 확인하고, 19→9 같은 비현실적인 변화·여러 숫자·다른 신호 혼입·만료 결과를 보류합니다. 점멸 여부를 확정하거나 신호를 실제 횡단보도와 지도상 연결하는 기능은 아직 없습니다.
- 0~9초가 확인되고 사용자가 **보도에서 대기**를 선택하면 다음 보행 신호를 기다리도록 안내합니다. 10초 이상 카운트다운/손 표시도 새 횡단을 권하지 않습니다. **횡단 중** 또는 **상태 미확인**은 다른 문구를 사용합니다. WALK도 관찰 안내이며 출발 명령이 아닙니다.
- STOP 후보와 최신 방향 센서가 있을 때 사용자가 스캔을 시작합니다. 기준 방향 대비 왼쪽→오른쪽→왼쪽 각도 범위에서 두 번씩 관찰해야 다음 단계로 넘어갑니다. 차량·자전거 후보 수를 음성으로 알리며 시간이 흘렀다는 이유만으로 완료하지 않습니다. 센서 누락/오래된 결과/사용자 상태 변경에서 중지합니다.
- 기본 객체와 확장 후보를 최대 10개 사각형으로 표시합니다. 한국어 이름과 단계, 우선 주의 빨강·주의 주황·참고 초록·확장 후보 파랑·일반 감지 밝은 회색을 함께 표시합니다. 거리 단위는 만들지 않습니다.
- 확장 시설물도 반복 관찰과 화면 중앙 아래 위치로 주의 후보를 선정합니다. 원래의 낮은 zero-shot 점수를 기존 COCO 신뢰도로 변조하지 않습니다. 기본 모델의 최신 우선 주의가 있으면 새 확장 자동 발화를 보류합니다. 음성 대기는 기존 한 개 채널을 공유하며 선택형 진동을 추가했습니다.

STOP 스캔은 정지한 차량이 재출발할지, 가려진 접근로가 있는지, 모든 진입로를 보았는지 확인하지 못합니다. 최종 문구는 ‘좌우 관찰을 마쳤으며 횡단 가능 여부는 확인하지 못했다’입니다. 시설물·보행 기호·숫자 판독은 잘못되거나 누락될 수 있으므로 아래 현장 검증은 남아 있습니다.

## 보도 시설물 확장

가로등의 얇은 기둥, 빈 자전거 거치대, 주차된 자전거와 겹친 거치대, 바퀴 달린/고정 쓰레기통, 보관함의 열린 문과 돌출부를 포함합니다. ‘시설물이 있다는 사실’과 ‘보행 공간을 막는 부분’을 구분할 수 있게 상자와 필요 시 영역·하단 위치를 라벨링합니다. 작은 기둥은 면적이 작더라도 제외하지 않는 방향으로 평가합니다.

개발 데이터는 사용 권한을 확인한 공개 데이터 또는 동의를 받은 직접 촬영 자료를 사용합니다. 회사 소스·사진·모델은 가져오지 않습니다. 장소·기기·조명 단위로 학습/튜닝과 평가를 분리하고, 대상별 미탐·오탐, 가림과 역광, 보도 중앙/측면의 단계 혼동을 기록합니다. 모델 교체나 추가는 Android의 처리 지연·발열·메모리 평가 후 선택합니다.

## 미국 보행 신호와 10초 기준

설계 근거: FHWA MUTCD 11판의 §4A.06은 보행 신호의 의미를, §4I.04는 카운트다운을 설명합니다. 점멸 손 표시는 새 횡단을 시작하는 구간이 아니며, 카운트다운은 이 전환 구간에 표시합니다. 이미 건너기 시작한 사람과 보도에서 기다리는 사람의 상황을 구분해야 합니다. [FHWA Part 4, 인쇄면 645·720](https://mutcd.fhwa.dot.gov/pdfs/11th_Edition/part4.pdf)

따라서 사용자가 요청한 **10초 미만이면 다음 신호 안내**를 추가적인 대기 안내 조건으로 채택하되, 10초 이상을 ‘건너도 됨’으로 바꾸지 않습니다. 10초는 사용자 요구에 따른 앱 기준이며 모든 사람·횡단보도의 충분한 횡단 시간을 뜻하지 않습니다. 실제 서비스 지역의 규정과 현장 접근성 신호도 별도로 확인합니다.

| 관찰과 사용자 상황 | 계획하는 처리 |
| --- | --- |
| 건너기 전이고 대상 보행 신호의 잔여 숫자가 반복 확인되어 0~9초 | “새로 건너지 말고 다음 보행 신호를 기다려 주세요.” 숫자가 불확실하면 초를 단정하지 않음 |
| 건너기 전이고 점멸 손·카운트다운 확인, 10초 이상 | 숫자와 관계없이 새 횡단을 시작하지 않는 안내 |
| 흰 보행자 또는 WALK가 반복 확인되고 대상 횡단 방향도 확인 | “보행 신호가 표시됐습니다.”라는 관찰 안내; 회전 차량 등을 추가 관찰하며 자동 횡단 허가로 바꾸지 않음 |
| 손 표시가 계속 켜져 있음 | 건너기 전 사용자에게 다음 보행 신호 대기 안내 |
| 이미 횡단 중임이 확인됨 | 보도에서 기다리는 안내와 분리. ‘다음 신호까지 그 자리에 대기’·갑작스러운 되돌아가기 지시를 하지 않음; 현장 신호와 위험 관찰 정보를 우선 |
| 사용자 위치/횡단 단계 미확인 | 조건 없는 정지·대기·출발 지시를 만들지 않고 상태 불확실성을 알림. 필요한 경우 “아직 건너기 전이라면…”처럼 조건을 명시 |
| 신호가 여러 개, 다른 횡단 방향, 숫자 가림/역광, 점멸 확인 불충분, 만료 결과 | 신호·시간 확인 불가. 반대편·옆 횡단보도 신호로 전환해 안내하지 않음 |

필요한 구현은 **보행 신호 영역 검출 → 대상 횡단보도/방향 연결 → 기호·문자 판독 → 숫자 OCR → 짧은 연속 관찰 확인 → 상황별 안내**입니다. 차량 신호의 녹색을 보행자 WALK로 사용하지 않습니다. 단일 사진에서 손 표시가 켜졌다고 점멸/고정을 확정하지 않으며, LED 깜박임·카메라 프레임 간격에 따른 판독 실패도 시험합니다.

9/19, 1/7, 0/8 등의 숫자 혼동과 신호 대상 바뀜을 검사합니다. 캡처 시각·처리 지연·발화 직전 유효시간을 유지하고, 오래된 숫자를 현재 잔여 시간처럼 읽지 않습니다. 보이지 않는 동안 무한히 카운트다운을 추정하지 않으며, 새 주기·대상 교체·추적 손실에서 숫자 근거를 초기화합니다. 현재 320×320 입력에서 멀리 있는 숫자가 작을 수 있으므로 신호 영역의 제한된 추가 판독을 검토하되 고해상도 영상 대기열은 만들지 않습니다.

## STOP 주변 스캔 안내

목표는 표지 발견 후 사용자가 도로에 들어가기 전 **좌측 → 우측 → 좌측 재확인 및 회전 차량 관찰**을 돕는 것입니다. NHTSA는 교차로에서 회전 차량과 가려진 다른 차량을 확인하고 표지·신호만 신뢰하지 않도록 안내합니다. [NHTSA 보행 안전](https://www.nhtsa.gov/road-safety/pedestrian-safety), [교차로와 회전 차량 안내](https://www.nhtsa.gov/pedestrian-safety/stepping-out-older-adult-be-healthy-walk-safely)

표지가 보였다는 것만으로 모든 진입로가 정지 통제인지, 차가 멈췄는지, 운전자가 양보하는지 알 수 없습니다. 다음 항목을 별도 근거로 다룹니다.

- 표지가 어느 차량 진입로를 향하는지, 사용자가 보도에서 기다리는지, 횡단 방향과 가장자리 위치.
- 좌·우·회전 진입로별 실제 관찰 범위와 관찰 시각. 일정 시간이 흘렀다는 이유만으로 스캔 완료 처리하지 않음.
- 카메라 회전과 차량 움직임 구분, 이동/정지/미확인 상태, 대형 차량 뒤 가림, 자전거·킥보드.
- 먼저 본 방향의 정보가 오래되면 다시 확인. 잠깐 정지한 차량의 재출발도 관찰.

음성은 ‘화면 오른쪽 차량이 움직입니다’, ‘왼쪽은 가려져 확인할 수 없습니다’처럼 근거와 누락을 전달하는 방향으로 설계합니다. 시야 밖 차량을 놓칠 수 있는 단일 카메라 스캔에서 ‘차가 없으니 건너세요’를 생성하지 않습니다. 사용자가 원하는 최종 횡단 보조는 위치·방향·가림·차량 추적 평가와 접근성 현장 검증을 거쳐 단계적으로 연결합니다. 시각장애 사용자에게 눈으로 확인하라는 요구를 대신하는 앱 관찰·음성 흐름을 설계하고, 카메라 방향 확인을 위해 도로로 이동하도록 요구하지 않습니다.

## 표시·알림·수용 검사

기존 React Native 화면과 주의 단계 이름을 유지합니다. 예시의 OpenCV/Flutter 코드와 JSON 형식은 필수 요구로 채택하지 않습니다. 색 이외에 단계·대상 글자와 음성을 함께 제공하고, 거리 근거가 없으면 ‘앞 1m’를 표시하지 않습니다. v0.4.7은 참고 초록·후보 파랑과 단계 글자를 함께 표시하며 저시력·색각·가독성 실기기 평가는 남아 있습니다.

다수 객체는 기존 우선순위 선택과 최신 대기 발화 1개 정책을 확장합니다. 긴 숫자 낭독으로 주변 소리를 가리지 않도록 신호 상태 변화와 10초 기준 진입 시의 짧은 안내를 검토합니다. 햅틱은 선택 가능하고 음성과 같은 유효 사건을 공유하며 반복 진동·종료 후 알림을 억제합니다. 위험 경고·신호 안내가 서로 모순되거나 횡단 중 불필요한 대기 지시를 내는지 별도로 검사합니다.

후속 검증에는 10→9 경계, 19→9 오독, 점멸 손+15초, WALK 숫자 없음, 이미 횡단 중·상태 미확인, 다른 방향 신호, 가려진 차량, 한 방향만 스캔, 차량 재출발, 렌즈 가림, 프레임 만료·앱 전환·음소거를 포함합니다. 실제 미국 신호와 교차로 자료에서 오독률·안내 지연·부적절한 출발/대기 안내를 따로 측정합니다. 정책 자동 검사만으로 현장 횡단 기능 완료를 선언하지 않습니다.
