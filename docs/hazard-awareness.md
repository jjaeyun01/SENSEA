# 영상 기반 위험 요소 관찰

2026-09-27 개발 기준. 사용자의 우선순위에 따라 Android에서 경로 안내보다 카메라에 보이는 위험 후보를 먼저 관찰하도록 확장했습니다. 이전 README의 정지 사진 설명 중심 계획은 이 기능의 개발 범위를 제한하지 않습니다. 현재 구현은 인식된 물체의 위치·반복 관찰·영상 크기 변화를 근거로 주의 정보를 만들며, 실제 충돌 여부를 검증한 제품은 아닙니다.

추적 구현은 [hazards.mjs](../mobile/src/vision/hazards.mjs), 대상·단계 정책은 [hazard-policy.mjs](../mobile/src/vision/hazard-policy.mjs), 입력 좌표 보정은 [detection.mjs](../mobile/src/vision/detection.mjs), 카메라 수명과 입력 제한은 [createNativeSession.ts](../mobile/src/vision/createNativeSession.ts)에 있습니다. 세부 임계값의 기준은 코드이며, 아래 설명에 적힌 제한 외의 검출 점수·크기·변화량 임계값은 아직 실기기 자료로 보정하지 않은 초기값입니다.

## 입력과 처리 순서

```text
후면 카메라 → 기존 실시간 미리보기
          └→ 방향 보정·320×320 입력 → 영상 품질 검사 → EfficientDet Lite0
                                                    └→ 최대 25개 탐지 후보
                                                        → 레터박스 제거·좌표 정규화
                                                        → 최대 12개 물체 추적
                                                        → 물체당 최근 4개 관찰
                                                        → 주의 후보 선정·중복 음성 억제
```

현재 모델은 COCO 계열 객체 라벨을 사용합니다. 모든 인식 라벨을 위험으로 취급하지 않으며, 사람·차량·자전거·동물·의자·가방 등 코드에 명시된 대상에서 주의 후보를 고릅니다. 모델의 탐지 신뢰도는 객체 분류의 필터와 비교 기준으로만 사용합니다. 이를 위험 확률이나 충돌 확률로 표시하지 않습니다.

이전 디코더의 기본 반환 제한 5개는 호환성을 위해 유지합니다. 실제 위험 분석 경로는 최대 25개를 요청하여, 인식 점수 순위가 낮다는 이유만으로 화면 아래쪽의 주의 후보를 먼저 제거하지 않도록 했습니다. 추적기에는 별도의 최대 12개 제한이 있으므로 복잡한 장면의 모든 객체를 추적한다는 의미는 아닙니다.

모델 박스는 처음에는 검은 여백을 포함한 320×320 정사각형 좌표입니다. 방향이 보정된 영상 크기로 축소 비율을 구하고, 정수 내림한 실제 내용 크기와 가운데 여백을 사용하여 `[top, left, bottom, right]`를 내용 기준 0~1 좌표로 바꿉니다. 일부만 여백에 걸친 박스는 내용 영역으로 자르고, 여백에만 있는 박스·역전된 박스·숫자가 아닌 좌표는 제거합니다. 세로·가로 화면과 좌우 회전 모두 같은 의미의 좌표를 사용합니다.

Android CameraX의 회전값은 이미지 버퍼에 적용할 시계방향 보정각입니다. 리사이저가 회전·미러를 적용한 뒤에는 박스 변환에서 이를 다시 적용하지 않습니다. [Android ImageInfo 공식 문서](https://developer.android.com/reference/androidx/camera/core/ImageInfo#getRotationDegrees())

## v0.4.6의 대상 분류와 지원 범위

사용자가 제안한 대상·거리·진로 간섭·이동성·3단계 우선순위·표시 상자를 기존 파이프라인에 흡수했습니다. 별도 AI 프롬프트를 전송하거나 API 응답을 0~1000 좌표 JSON으로 바꾸지 않습니다. 기존 `LiveResult` → `HazardAssessment`와 내용 기준 0~1 박스를 사용합니다.

| 구분 | 현재 모델로 구분하는 대상 | 아직 구분하지 못하는 요청 대상 |
| --- | --- | --- |
| 이동 가능 물체 | 사람, 자전거, 자동차, 오토바이, 버스, 트럭, 기차, 개, 고양이 | 전동 킥보드 |
| 길을 막는 물체 | 벤치, 의자, 화분, 소화전, 주차 요금기, 소파, 식탁, 침대, 여행 가방, 가방, 손가방, 우산 | 전선주, 가로등, 화단, 볼라드, 쓰레기통, 공사 콘·차단물 |
| 단차·낙차 | 없음 | 계단 위/아래, 연석, 열린 맨홀, 공사 낙차 |
| 머리 위 장애물 | 없음 | 낮은 나뭇가지, 차양, 열린 창문 |

이 표는 패키지의 `labels.json`과 대조한 분류 지원 범위이며 각 대상의 검출 성공을 보장하지 않습니다. 화분을 화단으로, 우산을 차양으로, 신호등을 가로등으로 바꿔서 지원한다고 표시하지 않습니다. `HAZARD_TARGETS`와 앱의 감지 범위 안내가 같은 목록을 사용합니다. 고정물 분류도 실제 정지 여부를 측정했다는 뜻은 아니며, `usually_static`/`dynamic_capable`로 표현합니다.

거리 대신 `imageScale`로 영상 면적을 기록하고, 실제 거리는 `distance: unknown`, `distanceMeters: null`을 유지합니다. 화면 중앙 아래의 사다리꼴 관심 영역과 물체의 수평 겹침을 비교해 `screenRelation`을 direct/offset/side/unknown으로 구분하되 실제 경로 간섭인 `pathInterference`는 unknown입니다. 관심 영역은 하단에서 넓어지며 휴대폰 방향·노면·발 위치를 추정하는 보행 경로 모델은 아닙니다.

현재 객체 탐지 출력은 상자·분류·분류 점수이며, 별도 깊이 측정을 연결하지 않았습니다. [Google 객체 탐지 문서](https://developers.google.com/edge/mediapipe/solutions/vision/object_detector). 향후 깊이 API를 쓰더라도 기기 지원 확인과 세션 설정이 필요합니다. [ARCore Depth 문서](https://developers.google.com/ar/develop/java/depth/developer-guide). 이를 근거로 현 버전에서 미터 거리나 임박한 충돌을 확정하지 않습니다.

## 반복 관찰을 이용한 판단

추적기는 같은 분류의 객체끼리 박스 겹침, 중심 위치, 크기 변화를 비교하고, 최근 중심 변화로 다음 위치의 대응 관계를 보완합니다. 서로 비슷한 객체가 겹치거나 대응이 모호하면 과거 관찰의 연속성을 초기화합니다. 한 프레임에서 놓친 객체의 이전 경고를 현재 관찰처럼 출력하지 않으며, 다시 나타나면 시간에 따른 변화 근거를 새로 모읍니다.

단일 탐지 한 번으로 위험을 확정하지 않습니다. 일반 주의는 최소 2개 관찰·180ms와 점수 조건을 만족해야 합니다. 크기 증가에는 최소 3개 관찰·400ms, 시작 대비 면적 비율 1.65 이상과 형태·점수·연속 변화 조건을 함께 요구합니다. 이 숫자는 실측 평가로 보정할 초기값입니다. 반복 관찰이 안정적일 때 다음과 같은 영상상의 단서를 함께 봅니다.

- 화면 중앙과 아래쪽에서 반복해서 보이는 물체
- 화면에서 차지하는 면적이 큰 차량이나 물체
- 형태와 위치가 비교적 일관된 채 여러 관찰에 걸쳐 커지는 물체
- 화면 주변에서 일정한 방향으로 영상 위치가 빠르게 변하는 이동 가능 물체
- 사람·개 등을 포함해 반복 관찰 중 화면 중앙 쪽으로 들어오는 물체
- 중앙 아래에 크고 지속적으로 보이는 벤치·화분 등의 고정물 후보

중앙·아래쪽 영역은 영상상의 관심 영역입니다. 휴대폰이 사용자의 진행 방향을 향한다는 확인이 없으므로 실제 보행 경로나 충돌 구역으로 해석하지 않습니다. 방향 안내도 “화면 왼쪽”, “화면 중앙”, “화면 오른쪽”으로 표현합니다.

크기 변화는 잘린 박스, 모호한 추적, 불안정한 모양에서 사용하지 않도록 제한합니다. 여러 객체가 함께 이동하거나 확대되는 장면에서는 휴대폰 회전·이동·줌의 영향을 의심하고 해당 변화 단서를 억제합니다. 이런 규칙으로 모든 카메라 움직임을 제거할 수는 없습니다. 객체가 적거나 배경과 움직임이 다른 장면에서는 잘못 판단할 수 있습니다.

v0.4.6은 작은 고정물이 면적만으로 모두 제외되지 않도록 초기 면적 하한을 고정물 0.012, 이동 가능 물체 0.025로 구분합니다. 화면 중앙으로 이동하는 단서는 최소 3개 관찰·400ms, 중심과의 거리 감소 0.08 이상, 관찰마다 0.02 이상의 일관된 감소, 겹침·점수·크기 연속성 조건을 요구합니다. 중앙을 넘어간 뒤에도 같은 방향으로 접근한다고 계속 추정하지 않습니다. 장면 전체 움직임과 잘린 상자에서는 이 단서를 억제합니다.

고정물 우선 주의는 중앙 영역, 최소 3개 관찰·400ms, 모든 점수 0.82 이상, 장면 이동 없음, 마지막 2개 관찰 모두 하단 0.88 이상·면적 0.18 이상을 요구합니다. 중앙의 이동 가능 물체는 면적 0.10 이상과 강한 점수·크기 증가 또는 중앙 쪽 이동 근거로 우선순위가 오릅니다. 기존 큰 차량의 반복 확인 규칙도 유지합니다. 모두 합성 입력으로 검증한 초기 규칙이며 실물 거리 기준이 아닙니다.

## 상태와 음성

| 상태 | 의미 | 해석하면 안 되는 내용 |
| --- | --- | --- |
| `unavailable` | 최신의 유효한 영상 근거가 없거나 영상 품질·분석 상태 때문에 판단할 수 없음 | 위험이 없음 |
| `observing` | 영상은 유효하지만 현재 주의 규칙을 충족한 반복 근거가 없음 | 길이 비어 있음, 이동 가능 |
| `notice` | 반복해서 보이지만 주의 조건이 약한 주변 물체를 참고로 표시 | 측면이므로 안전함 |
| `caution` | 반복 관찰과 위치·크기 등의 단서로 주의를 줄 후보가 있음 | 실제 거리나 충돌 여부 확정 |
| `priority` | 큰 고정물·중앙 쪽으로 이동하는 물체·큰 차량 등 더 강한 조건을 충족해 먼저 알려야 할 후보가 있음 | 실제 충돌이 임박했다는 확정 |

`navigation_safe`는 항상 `false`입니다. 감지하지 못한 경우에도 “위험 요소를 관찰 중입니다. 감지되지 않은 위험이 있을 수 있습니다.”처럼 판단 범위를 밝힙니다. 영상 크기가 커질 때는 그 변화를 말하고 화면의 상세 근거에 실제 거리는 알 수 없다고 안내합니다. 자동 음성은 “우선 주의. 화면 중앙 자동차. 화면에서 커져 보입니다.”처럼 짧게 읽으며 수동 다시 듣기는 상세 근거를 제공합니다. 인식되지 않은 객체가 없다고 결론 내리지 않습니다.

`notice` → `caution` → `priority`는 각각 참고·주의·우선 주의입니다. 상대적 정렬 점수 `priorityScore`는 1~3/5~7/8~10 대역이며 충돌 확률이나 공인 위험 척도가 아닙니다. 점수 숫자는 사용자 화면에 노출하지 않습니다. `confirmedCount`는 최대 12개 추적 대상 중 반복 근거를 충족한 수, `warningCount`는 그중 주의·우선 주의 수이고, 화면에는 상위 3개만 표시합니다. 현장의 위험 총개수가 아닙니다.

`notice`는 자동 경고 음성을 사용하지 않고 화면·수동 다시 듣기로 제공합니다. 더 높은 단계가 먼저 정렬되며 현재의 주의 대상이 참고 단계로 낮아지면 이전 경고 발화를 취소합니다. `action`/`guidance`는 우선 대상 확인·주변 확인·관찰·영상 상태 확인을 안내합니다. 회피 방향·통행 가능·즉시 정지를 계산한 것으로 표현하지 않습니다.

위험 안내에는 객체 추적 ID와 방향을 사용해 중복을 억제합니다. 기본 간격은 일반 주의 4초, 같은 경고 8초이며 우선순위 상승에는 별도 1.5초 제한을 둡니다. 우선순위가 높아진 새 근거는 일반 관찰 음성의 대기보다 먼저 처리하고, 같은 단서를 계속 감지할 때도 음성을 무제한 적재하지 않습니다. [speech-channel.mjs](../mobile/src/vision/speech-channel.mjs)는 최신 발화 하나만 대기시키고 음성 엔진 중지 후 실제 발화 직전에 신선도를 다시 확인합니다. 만료·음소거·교체·실패로 발화를 버리면 해당 경고의 발화 예약을 복원해 다음 유효 결과를 다시 안내할 수 있게 합니다. 세대 번호로 이전 취소가 더 최신 경고의 예약을 지우지 않도록 합니다. 일반 객체·영상 품질 안내에도 같은 미전달 복원 정책을 별도 세대 번호로 적용합니다. 음성 중지 지연이나 오류로 품질 발화가 사라지면 다음 유효 결과의 반복 확인부터 다시 시도하며, 이전 취소가 새 품질 안내를 초기화하지 않게 합니다. 화면 종료·분석 오류·결과 만료에서는 앱 안의 대기 발화와 자체 TTS를 취소합니다. 다만 Android에서 이미 TalkBack에 전달한 접근성 공지는 자체 TTS의 `stop()`으로 강제 취소할 수 없습니다. `queue: false` 지정만으로 진행 중인 TalkBack 발화의 즉시 중단을 보장하지 않으며, 실제 기기의 화면 읽기 동작은 별도 확인이 필요합니다.

TalkBack 사용 시 주의 알림과 영상 품질 안내는 접근성 공지로 전달하고 Expo TTS를 겹쳐 재생하지 않습니다. 양호한 영상의 일반 객체 목록은 자동 공지를 억제하고 수동 다시 듣기로 제공합니다. 영상 품질 상태나 원인이 바뀌면 이전 품질 안내를 취소하고 일반 음성 확인 상태를 초기화하여, 렌즈 가림이 회복된 뒤 다시 가려져도 새 안내를 제공하도록 했습니다. 자동 알림 끄기가 적용되며 수동 다시 듣기는 계속 사용할 수 있습니다.

## 미리보기 표시

`LiveResult.imageSize`는 방향을 보정한 영상 크기이며 픽셀이 아닙니다. [preview-geometry.mjs](../mobile/src/vision/preview-geometry.mjs)는 이를 실제 미리보기 레이아웃의 `cover` 확대·중앙 잘림에 맞춰 투영합니다. 0~1 상자를 화면 픽셀로 변환하고 화면 밖·잘못된 상자는 제외하며, 색과 글자로 단계·대상을 함께 표시합니다. 화면 읽기에는 중복 상자를 숨기고 텍스트 카드와 기존 음성 경로를 제공합니다. 기존 결과 만료·중지에서 상자도 함께 지워집니다.

이 상자는 분석 프레임 기준이므로 더 최신인 미리보기와 시간차가 날 수 있습니다. 후면 카메라의 회전된 내용 좌표와 중앙 cover 크롭을 전제로 하며, 실기기별 카메라 출력 화각·손떨림 보정 차이에 따른 정합은 별도 확인해야 합니다. 실제 물체·상자의 정확한 일치나 보행 경로를 검증한 표시는 아닙니다.

## 시간과 메모리

| 항목 | 제한 또는 의미 |
| --- | --- |
| 모델에서 위험 분석으로 전달하는 탐지 후보 | 최대 25개 |
| 추적 객체 | 최대 12개 |
| 한 번에 반환하는 주의 후보 | 최대 3개 |
| 객체당 관찰 기록 | 최대 4개, 합계 최대 48개의 작은 메타데이터 기록 |
| 위험 분석 입력의 유효시간 | 프레임 콜백 시작 시각부터 1초 |
| 이미지 기록 | 위험 추적기에 픽셀·사진·base64·동영상 누적 없음 |
| 모델 입력 | 기존 320×320 RGB 버퍼를 재사용 |

`receivedAt`은 프레임 콜백이 시작될 때 기록한 시각입니다. 모델 실행이 끝난 시각으로 다시 찍어 느린 결과를 새것처럼 보이게 하지 않습니다. 미래 시각, 만료된 결과, 잘못된 품질 상태에서는 위험 판단 기록을 초기화합니다. 같은 결과를 여러 번 입력하거나 시각이 거꾸로 온 결과로 반복 관찰 근거를 늘리지 않습니다.

사용자가 허용한 약 4초의 설치 시험 지연과, 현재 상황을 말하는 위험 안내의 유효시간은 별개입니다. 4초 된 화면 분석을 현재의 위험 정보로 안내하지 않습니다. 위험 분석의 1초 제한을 유지하며, 기존 카메라 분석은 결과가 1초를 연속 3회 초과하면 분석을 중지하고 미리보기를 유지합니다. 따라서 느린 기기에서는 화면이 보여도 위험 관찰을 제공하지 못할 수 있습니다.

4GB를 프레임 저장용으로 확보하거나 그만큼 쌓인 뒤 버리는 방식은 사용하지 않습니다. 추적기 제한은 앱 전체 RSS·카메라 드라이버·모델 텐서·OS 영상 풀의 메모리 상한을 뜻하지 않습니다. 전체 메모리, 발열, 배터리, 지속적인 처리 지연은 실제 휴대폰에서 별도로 측정해야 합니다.

## 기존 백엔드와의 역할

백엔드의 [POST /vision/describe](../backend/app/main.py)는 사용자가 멈춘 상태에서 요청하는 정지 사진 설명 API입니다. [vision.py](../backend/app/vision.py)는 읽을 수 있는 간판·장소·출입구를 설명하고, 불확실할 때 이를 표시하도록 구성되어 있습니다. 위험 추적·충돌 점수 계산 API는 기존 백엔드에 없습니다.

응답의 `roadway`와 `sidewalk`는 정지 사진에 대한 `detected`·`not_detected`·`uncertain` 관찰 값입니다. 차도·인도 픽셀 영역을 구분하는 분할 모델이 아니며, 실시간 위험 판단의 근거로 연결하지 않았습니다. 현재 위험 분석은 휴대폰 안에서 진행하므로 매 프레임의 서버 왕복이나 외부 AI 호출이 필요하지 않습니다.

## 인식 범위와 한계

현재 COCO 객체 탐지 모델에는 계단·낙차·포트홀·연석·차도·인도를 별도로 판별하는 이 기능용 클래스가 없습니다. 낮은 장애물, 작은 물체, 역광 속 물체, 가려진 물체, 모델이 학습하지 못한 형태도 놓칠 수 있습니다. 이런 대상을 다루려면 해당 클래스와 장면이 포함된 별도 데이터·모델 및 검증이 필요합니다.

2D 박스 면적 증가는 객체 접근 외에도 카메라 이동, 줌, 자세 변화, 가림 해제, 검출 흔들림으로 생깁니다. 현재 앱은 카메라 보정값·객체의 실제 크기·깊이를 이용한 거리 복원을 수행하지 않습니다. 따라서 미터 단위 거리, 실제 속도, 충돌까지 남은 시간(TTC), 회피 방향을 산출하지 않습니다.

OpenCV의 투영 모델은 3D 장면이 카메라 내부·외부 파라미터를 통해 2D로 투영되는 관계와 크기 모호성을 설명합니다. 이를 근거로 이 구현에서는 박스 변화만으로 물리 거리와 충돌 시간을 확정하지 않는 설계를 선택했습니다. OpenCV를 새 런타임 의존성으로 넣었다는 뜻은 아닙니다. [OpenCV Camera Calibration and 3D Reconstruction](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)

같은 영상의 인접 프레임을 무작위로 학습·튜닝용과 평가용에 나누지 않고, 촬영 장면·장소·기기 단위로 분리합니다. 임계값을 조정한 뒤에는 따로 남겨 둔 장면으로 다시 평가합니다. 원본 영상과 객체 라벨을 대조해 모델의 미탐과 추적·주의 규칙의 누락을 구분하고, “유효한 경고 이벤트”의 기준을 시험 전에 정합니다. 정밀도는 발생시킨 경고 중 기준에 맞는 비율, 재현율은 정답으로 표시한 사건 중 경고를 낸 비율로 보고하며, 사건의 개수와 누락 사례도 함께 남깁니다.

최초 실기기 시험은 촬영자가 주변을 직접 확인할 수 있는 통제된 공간에서 진행합니다. 접근성 평가는 기기 성능 평가와 별도로 한국어 음성의 길이, TalkBack 상태 안내, 방향 표현의 이해도, 잦은 경고의 피로도를 확인합니다. 실제 보행 보조 성능이나 인증을 검증한 것으로 표현하지 않습니다.

회사 소스·내부 데이터·내부 모델은 사용하지 않았습니다. 현재 알고리즘과 테스트는 이 저장소에서 작성한 코드이며, 공개 모델과 공개 API 문서를 바탕으로 개발합니다.

## v0.4.8 가까운 위험 진동

- 기본 감지와 확장 시설물 감지가 같은 진동 채널을 사용합니다. `가까운 위험 진동`은 기본 켜짐이며 자동 음성·화면 읽기 설정과 독립적으로 동작합니다.
- 최신 관찰에서 화면 중앙 영역의 우선 주의 대상이 확인되면 Android에서 180ms 진동 → 100ms 간격 → 180ms 진동을 출력합니다. 자동 반복 패턴이나 대기 진동 큐는 없습니다.
- 화면 중앙 아래에 크게 보이는 사람·동물도 고정물처럼 3회 이상·400ms 이상 반복 관찰하고, 최근 두 상자가 중앙 영역·하단 88% 이상·영상 면적 18% 이상이며 점수 0.82 이상일 때 우선 주의로 처리합니다. 장면 전체 움직임이 있으면 이 조건을 보류합니다. 기존 차량·중앙 진입/영상 크기 증가 규칙도 유지합니다.
- 두 모델·여러 객체의 진동은 최소 1.8초 간격을 공유합니다. 같은 타임스탬프나 역순 결과로 반복 진동을 만들지 않습니다. 재진동에는 새롭고 유효한 관찰이 필요합니다.
- 최신 위험이 사라지거나 결과가 1초를 넘기면 진행 중 진동을 취소합니다. 다른 모델의 유효한 위험이 남아 있으면 그 경고는 유지합니다. 카메라 종료·결과 지우기·안내 열기·백그라운드 전환·진동 설정 끄기에도 중지합니다.
- 일반 사물 목록·보행 신호 상태·STOP 스캔 단계 전환은 충돌 주의 진동을 발생시키지 않습니다.

실제 거리나 충돌 확률을 계산한 기능은 아니며, 카메라 화면의 반복 관찰을 이용한 주의 표시입니다. 구현은 [collision-haptics.mjs](../mobile/src/vision/collision-haptics.mjs)에 있으며, 15개 관련 검사를 포함한 모바일 212개 테스트와 TypeScript 검사를 통과했습니다.
