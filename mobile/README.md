# SENSEA 모바일 카메라

현재 Android 설치 파일: `build/android/SENSEA-android-v0.4.11.apk`(저장소 루트 기준 로컬 경로). 앱 화면·객체 이름·접근성 문구·위험/신호/STOP 음성 안내를 영어로 전환했습니다. 근접 후보 처리와 진동 1.2초 간격은 유지합니다. 사람은 인식·표시·위험 진동을 유지하되 자동 음성 안내에서는 제외합니다. 직접 누르는 다시 듣기에는 사람도 포함됩니다. 기존 앱 위에 업데이트 설치할 수 있습니다. 제작·검사 기록은 [README1](../README1.md)에 있습니다.

Android와 iPhone의 후면 카메라를 연결한 Expo/React Native 앱입니다. 현재 v0.4.11 개발 우선순위는 **Android의 위험 요소 관찰**입니다. 후면 카메라 → 로컬 품질 검사 → EfficientDet Lite0 객체 탐지 → 제한된 객체 추적·주의 후보 선정 → 영어 화면·영어 음성 안내를 연결했습니다. 카메라를 켜면 **실시간 미리보기를 먼저 표시한 뒤** 분석을 준비하고, 끄거나 앱이 백그라운드로 이동하면 입력과 음성을 중지하고 네이티브 자원을 반환합니다.

최대 초당 5회만 분석하며 처리 중 들어오는 프레임은 네이티브에서 버립니다. 이미지 파일·base64·영상 기록을 만들거나 서버로 전송하지 않습니다. 모델은 앱에 포함되므로 설치 후 분석에 네트워크가 필요하지 않습니다. ML Kit SDK는 Google에 성능·사용 통계를 전송할 수 있으며 앱의 개인정보 안내에 고지합니다. Android 설치형 앱에서는 expo-asset으로 공개 모델만 로컬 캐시에 풀어 file:// 경로로 읽습니다. 카메라 영상 캐시는 만들지 않습니다.

현재 모델은 사람·차량 등 COCO 객체를 분류합니다. 최대 25개 탐지 후보에서 12개 객체의 최근 4개 관찰만 추적하고 최대 3개 주의 후보를 선정합니다. 반복 관찰·화면 관심 영역·영상 크기 변화·중앙 쪽 이동을 활용하는 초기 규칙이며 실제 위험 경고 정확도는 검증하지 않았습니다. 측면 참고 물체는 자동 음성을 쓰지 않으며, 큰 고정물과 중앙으로 들어오는 사람·개 등의 우선순위를 별도로 판단합니다. 기본 주의 대상은 최대 3개로 선정하고 일반·확장 후보를 포함해 최대 10개 사각형을 표시합니다. 앱의 감지 범위에서 지원 대상과 미지원 대상을 구분합니다. 계단·낙차·포트홀·차도/인도 영역 분할, 실제 거리·충돌 시간/확률 계산, GPS 길안내는 아직 연결하지 않았습니다. 신호 OCR은 아래 Android 확장 분석에 포함됩니다. 신호등 객체 인식은 신호 색이나 횡단 가능 판정이 아닙니다.

## 표시 언어와 음성 (v0.4.11)

앱 화면과 안내 내용은 영어입니다. 기기가 제공하는 미국 영어 음성을 우선 선택하고, 없으면 다른 영어 음성을 사용합니다. Android에서 Expo Speech의 지역 태그 처리로 휴대폰 기본 언어에 되돌아가지 않도록 `en`과 선택한 영어 voice ID를 전달합니다. iPhone 언어 지정은 `en-US`입니다. 음성 목록 조회 실패 시에도 영어 언어 지정을 유지합니다. 목록의 음성이 실제 합성 요청을 거부하면 다음 최신 안내부터 기본 영어 음성으로 전환합니다. 오래된 위험 경고를 재시도하지 않습니다.

TalkBack/VoiceOver를 사용할 때는 영어 안내 내용을 화면 읽기 시스템에 전달하며 실제 발음은 해당 시스템의 언어 설정을 따릅니다. OS 권한 창의 언어는 휴대폰 설정을 따릅니다. 영어 문구와 음성 선택 로직을 검사했으며 실제 휴대폰의 오디오 출력은 별도 실기기 검증을 하지 않았습니다.

## 실행

Node.js 22를 사용합니다. Android는 8.0(API 26) 이상입니다. Android 프레임 변환은 CPU에서 수행하고, 모델은 XNNPACK 2개 스레드로 실행하며 초기화 실패 시 기본 CPU로 대체합니다. iOS 프레임 변환은 기존 GPU 경로를 사용합니다. 모델 준비에 실패하거나 분석이 연속 3회 1초를 초과하면 미리보기를 유지하고 분석 중지를 안내합니다. 네이티브 카메라 모듈이 있으므로 **Expo Go에서는 실행할 수 없습니다**.

```sh
cd mobile
npm ci
npm run models:download
# Android SDK/JDK가 있는 컴퓨터 + USB 디버깅 휴대폰
npm run android -- --device
# macOS + Xcode + 개발용 서명 설정 + 연결된 iPhone
npm run ios -- --device
```

npm ci의 postinstall은 고정된 fast-tflite 3.0.1에 Android CPU 패치를 적용합니다. 원본 버전과 전체 해시가 다르면 설치를 중단하므로 의존성 업그레이드 시 [패치 설명](native/tflite-cpu/README.md)을 먼저 확인하세요. 최초 모델 다운로드는 SHA-256과 파일 크기를 검증합니다. 모델을 지웠으면 다시 다운로드한 뒤 빌드합니다. 개발 빌드를 설치한 후에는 `npm start`로 Metro에 연결합니다. Google Drive 같은 동기화 폴더에서 npm 설치 오류가 나면 저장소를 일반 로컬 디스크에 복제해 실행하세요.

GitHub Actions의 **SENSEA native camera**는 Android 네이티브 컴파일을 자동 수행합니다. Android 우선 개발 방침에 따라 iOS 시뮬레이터는 해당 워크플로의 수동 실행, iPhone IPA는 별도 워크플로의 수동 실행으로 유지합니다. Android 성공 실행의 `sensea-android-arm64-demo` 아티팩트는 개발 키로 서명된 테스트 APK이며 앱스토어 배포용이 아닙니다. iOS 아티팩트는 시뮬레이터용으로, 별도 iPhone test package 워크플로는 개인 서명용 IPA를 만듭니다. [Windows 설치 안내](../docs/iphone-testing.md)를 확인하세요.

## 확장 분석 (v0.4.7)

Android에서 기본 분석이 안정적으로 동작하면 OWL-ViT INT8 + ML Kit OCR를 실행합니다. 기본 분석이 느려지거나 최신 결과가 끊기면 확장 분석을 대기시키고 기본 위험 분석을 우선합니다. 한 프레임만 처리하며 늦은 결과는 버리고, 느린 기기에서는 확장 기능을 중지합니다. 보행 신호 패널에서 대기/횡단 중을 선택하고 STOP 스캔을 수동 시작할 수 있습니다. 모델과 신호 처리는 시험 단계입니다. 실제 도로 횡단 허가나 미터 단위 거리를 제공하지 않습니다. 자세한 구현·남은 평가는 [미국 교차로 문서](../docs/us-crossing-roadmap.md)를 참조하세요.

## 개인정보와 접근성 (v0.4)

처음 카메라를 켜기 전에 앱 내 이용 안내를 확인합니다. 안내 확인 상태는 앱 세션에만 유지하며 권한 승인은 별도 OS 창에서 받습니다. 처음 뜬 안내의 **Accept and start camera**을 누르면 바로 권한 요청과 실시간 미리보기가 이어집니다. 시작·취소 버튼은 안내 스크롤 아래에 고정되어 있습니다. 안내를 취소하면 카메라를 열지 않습니다.

- **Privacy and usage / Open-source notices**를 열면 카메라와 음성이 정지합니다.
- **Stop analysis and clear results**는 진행 중 입력·자체 TTS·앱 안의 대기 음성을 멈추고 표시 결과와 제한된 추적 메타데이터를 지웁니다. 사진이나 지속적인 분석 기록은 저장하지 않습니다.
- TalkBack/VoiceOver가 켜져 있으면 주의 알림과 어두움·과노출·정보 부족 등의 영상 품질 안내를 화면 읽기 시스템으로 전달하고 Expo TTS와 중복 재생하지 않습니다. 일반 객체 목록의 자동 읽기는 억제하며 **Replay**로 확인할 수 있습니다. 자동 알림을 꺼도 수동 다시 듣기는 사용할 수 있습니다. Android에서 이미 TalkBack에 전달된 발화는 앱이 강제로 취소할 수 없습니다.
- Android는 사용하지 않는 마이크·위치·사진 라이브러리 권한을 manifest에서 차단합니다. 카메라 권한만 기능 사용 시 요청합니다.
- 실제 기기에서 초점 이동·모달 닫기·큰 글씨·음성 겹침 검증은 [접근성 시험 계획](../docs/accessibility-test-plan.md)에 남아 있습니다.

## 조작

- **Turn on camera**: 권한 요청 후 후면 카메라 영상을 먼저 표시합니다. 네이티브 첫 영상 수신을 확인한 뒤에만 켜짐으로 표시하고 분석을 시작합니다.
- **주의 상태**: 확인할 수 없음·연속 관찰 중·주의 대상 감지·우선 확인 단계와 근거를 표시합니다. 위치는 실제 보행 방향이 아닌 화면 왼쪽/중앙/오른쪽입니다.
- **음성 안내**: 사람은 자동 음성에서 제외하며 인식·사각형·가까운 위험 진동은 유지합니다. 직접 누르는 다시 듣기에서는 사람도 확인할 수 있습니다. 연속 확인된 다른 주의 후보를 일반 객체 설명보다 먼저 짧게 읽습니다. 최신 대기 발화는 하나이며, 일반 주의는 최소 4초·같은 주의는 8초, 우선순위 상승은 별도 1.5초 제한을 적용합니다. 자동 음성을 끄면 화면 읽기 자동 주의 알림도 꺼집니다. 주의·일반 객체·영상 품질 안내가 발화 전에 만료되거나 취소·실패하면 해당 예약을 복원해 다음 유효 결과에서 다시 확인합니다.
- **Nearby hazard vibration**: 기본 켜짐이며 자동 음성과 별도로 동작합니다. 기본·확장 분석의 가까운 우선 주의에 180ms 두 번 진동하며 최소 1.2초 간격을 공유합니다. 위험이 사라지거나 만료되면 중지하고, 카메라 종료·백그라운드·설정 끄기에서도 취소합니다.
- **Replay**: 1초 이내 현재 주의 근거를 우선 읽고, 주의 후보가 없으면 현재 일반 분석 결과를 읽습니다.
- **Turn off camera**: 처리 중인 프레임의 사용이 끝난 뒤 카메라·모델·변환 자원을 반환합니다. 앱 복귀 후 자동으로 카메라를 다시 켜지 않습니다.
- **Open-source notices**: 사용 모델과 직접 의존 라이브러리의 라이선스를 확인합니다.

## 검증

```sh
npm run typecheck
npm test
npm run export:check
# Linux/macOS에서 실제 모델 계약 확인 (CI에도 포함)
python -m pip install ai-edge-litert==1.4.0 numpy==2.2.6
python scripts/check-model.py
```

추가된 **Android live camera smoke** 워크플로는 API 35 에뮬레이터의 가상 카메라로 안내 취소·권한 허용·첫 영상 표시·매 재시작의 새 추론 결과·분석 유지·꺼짐·앱 전환을 검사하고 화면과 로그를 남깁니다. 실행 결과는 GitHub Actions에서 확인합니다.

v0.4.10 소스의 231개 테스트와 TypeScript 검사가 통과했습니다. 이전 v0.4.8 APK는 공개 사진을 입력한 에뮬레이터에서 기본·확장 모델의 3세션 설치/추론/재시작 검사와 사각형 표시 확인을 통과했습니다. 진동 기본 켜짐·음성 끄기와 독립된 설정·진동 스위치도 확인했으며 실제 휴대폰의 진동 감각은 검증하지 않았습니다. 단위 검사는 오류·스킵·1만 프레임 유입 시 메모리 반환, 작은 출력만 전달, 좌표 변환, 추적·주의 규칙, 음성 우선순위·반복·취소·만료를 확인합니다. [v0.4.4 APK](../build/android/SENSEA-android-v0.4.4.apk)의 버전·서명·권한·번들 검사와 에뮬레이터 3세션의 최신 추론·재시작·앱 전환 검사를 통과했습니다. 첫 처리 208~346ms는 4코어·host GPU 에뮬레이터의 세션별 관측값이며 실폰 성능이나 위험 인식 정확도 측정이 아닙니다. 최종 결과는 [README1](../README1.md)에 기록했습니다. 번들·컴파일 성공은 실기기 성능 검증을 대체하지 않습니다. 실제 Android/iPhone에서 권한 거절·재허용, 카메라 50회 열기/닫기, 앱 전환, 20분 연속 실행, VoiceOver/TalkBack과 큰 글꼴, 지연·발열·메모리 추이를 확인해야 합니다.

v0.4.9 APK의 소스·번들·서명·모델 검사는 통과했습니다. 이번 에뮬레이터에서는 첫 추론 이후 처리 시간 초과로 지속 분석 검사가 실패했으며, 같은 환경의 이전 v0.4.8에서도 재현됐습니다. 상세 실패·비교 기록은 [README1](../README1.md)에 있습니다.

v0.4.10 최종 APK는 새 추론·지속 분석·재시작·백그라운드 중지/복귀의 기본 카메라 3세션 검사를 통과했습니다. 확장 모델은 두 세션에서 실제 추론을 확인했고 한 세션은 기본 분석 우선 대기로 기록했습니다. 검사 중 확장 분석이 느려 중지된 구간도 있었으며, 이 결과를 확장 모델이 계속 동작한 것으로 표현하지 않습니다. 실기기 근거리 인식 정확도와 진동 감각은 검사하지 않았습니다.
