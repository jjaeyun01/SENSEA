
## 4. 백엔드 기본 구조·데이터·API

### 4.1 서버 기반

FastAPI와 Pydantic으로 입력·출력 계약을 정의했습니다. 환경변수는 설정 객체로 관리하고, 외부 AI 키는 서버에만 둡니다. 요청 오류는 공통 `error.code`/`error.message` 형식으로 반환하며 이미지 내용이나 인증 정보를 오류에 그대로 넣지 않습니다.

구현 파일: [main.py](backend/app/main.py), [config.py](backend/app/config.py), [models.py](backend/app/models.py), [errors.py](backend/app/errors.py).

### 4.2 가상 데이터와 저장소

- 목적지 2개: 예시 도서관, 예시 카페.
- 지점 5개: 출발점, 광장, 정원, 도서관 입구, 카페 입구.
- 연결 구간 5개와 양방향 안내 문장을 준비했습니다.
- 실제 좌표는 넣지 않았으며 장소의 좌표는 `null`입니다.
- 경로 요청에는 `simulation=true`가 필요하고 응답은 `simulation_only=true`입니다.
- 소음은 구간별 0~1 상대값만 받습니다. 원시 오디오·사용자 ID·개인 GPS는 받지 않습니다.
- 저장소는 단일 프로세스 메모리 방식이며 재시작하면 업로드한 값이 유지되지 않습니다.

관련 파일: [demo.json](backend/app/data/demo.json), [db.py](backend/app/db.py).

### 4.3 DB 스키마 초안

[001_initial.sql](backend/migrations/001_initial.sql)에 다음 테이블을 작성했습니다.

| 테이블 | 목적 |
|---|---|
| `places` | 목적지·입구 waypoint 연결 |
| `waypoints` | 보행 지점·랜드마크·검증 시각 |
| `path_edges` | 연결 구간·거리·양방향 안내·보행 검증 여부와 시각 |
| `noise_observations` | 구간별 상대 소음 요약값·관측 시각 |

좌표·거리·소음값의 범위, 외래키, 양방향 안내, 검증 날짜 조건을 넣었습니다. RLS를 활성화하고 모바일의 직접 접근 권한을 차단하는 초안도 포함합니다. **실제 DB에 적용하거나 Supabase 어댑터를 연결한 상태는 아닙니다.**

### 4.4 API별 작업

| API | 작성한 처리 | 현재 사용 조건 |
|---|---|---|
| `GET /health` | 서버 상태·데모 모드·사진 제공자 설정 여부 | 설정 여부는 실제 외부 AI 호출 성공과 다름 |
| `GET /places?q=...` | 대소문자를 구분하지 않는 가상 목적지 검색 | 현재 가상 장소만 검색 |
| `POST /routes` | 출발·도착 검증, 경로 계산·비교, 소음·거리·구간 안내 반환 | `simulation=true` |
| `POST /noise` | 동의·구간·값 범위 검사, 요약값 저장·집계 | `consent=true`, `relative_noise` 0~1 |
| `POST /vision/describe` | 사진 검증·품질 검사·외부 설명·요청 ID 반환 | 정지 확인, 외부 전송 동의, 제공자 설정 필요 |
| `POST /speech/transcribe` | 미연결 상태를 오류로 알리는 자리 마련 | `501 speech_not_configured`, STT 구현 아님 |
| `GET /docs` | Swagger API 확인 화면 | 실행 중인 서버에서 접근 |

실행·요청 예시는 [backend/README.md](backend/README.md)에 있습니다. 외부 AI 기본값은 비활성화이며, 품질 검사를 통과한 사진 설명은 설정 전까지 `503 vision_not_configured`를 반환합니다.

## 5. 최단 경로·소음 가중 경로 계산

[routing.py](backend/app/routing.py)에 Dijkstra 기반 탐색을 구현했습니다.

```text
구간 비용 = 거리 × (1 + 소음 가중치 × 상대 소음값)
최단 경로: 소음 가중치 0
소음 가중 경로: 소음 가중치 2
```

- 기본 예제에서 최단 경로는 **200m**, 소음 가중 경로는 **280m**입니다. 모두 가상 거리입니다.
- 두 계산 결과가 같으면 경로를 중복 반환하지 않습니다.
- 소음값이 없거나 오래됐으면 비용 계산에서 0으로 처리하지 않고 1을 사용합니다.
- 응답의 소음 평균은 측정된 구간의 거리로 가중하며 `noise_coverage`와 관측 시각을 함께 반환합니다.
- 역방향 경로에는 별도로 작성된 역방향 안내를 사용합니다.
- 실제 경로 모드의 알고리즘은 미검증 구간, 검증 날짜 누락, 미래 시각, 만료된 검증을 제외합니다.
- 보행 검증의 기본 기한은 24시간이며 설정으로 변경할 수 있습니다. 이 기한은 시험용 재검토 규칙입니다.

경로를 AI가 생성하도록 하지 않았고, 소음값을 혼잡 인원수나 통행 안전으로 해석하지 않았습니다. 실제 도로 데이터와 GPS가 연결된 길안내는 다음 단계입니다.

## 6. 카메라·모델·실시간 메모리 처리

### 6.1 실제 앱에 구현한 기능

[App.tsx](mobile/App.tsx)에 후면 카메라 미리보기, 권한 요청, 켜기/끄기, 객체 결과 표시, 주의 단계·근거 표시, 우선순위 자동 음성, 다시 듣기, 개인정보 안내, 오픈소스 안내를 구성했습니다. v0.4.4의 [hazards.mjs](mobile/src/vision/hazards.mjs)는 연속 관찰과 영상상 위치·크기 단서를 결합합니다. 규칙은 아직 실측 자료로 보정하지 않은 초기값이며 실제 충돌 예측기로 검증하지 않았습니다.

기술 구성은 Expo 57, React Native 0.86.3, TypeScript, VisionCamera 5.2.3, fast-tflite 3.0.1, Expo Speech입니다. 정확한 고정 버전은 [package.json](mobile/package.json)과 lockfile에 있습니다.

현재 모델이 찾는 것은 사람·자동차·자전거 등 COCO 객체입니다. 신호등 객체를 찾는 것과 신호 색·횡단 가능 여부를 판단하는 것은 구분합니다. 차도/인도 영역 분할, OCR, 거리·충돌 시간 계산은 현재 앱에 없습니다.

### 6.2 공개 모델과 자료 사용

- 모델: **TensorFlow EfficientDet Lite0 V1**, 메타데이터와 NMS가 포함된 배포본.
- 입력: `uint8`, `1×320×320×3` RGB.
- 출력: 위치·분류·점수·탐지 개수, 최대 25개 후보.
- 모델 크기: **4,563,519바이트**.
- 출처·라이선스: 원본 메타데이터의 TensorFlow / Apache-2.0 표기를 확인하고 고지 포함.
- 다운로드 시 파일 크기와 SHA-256을 검증하며 앱에 모델을 묶어 배포합니다.
- 회사 프로젝트의 소스·사진·학습 데이터·가중치·내부 문서는 가져오지 않았습니다.
- 품질 검사와 비동기 제어는 일반적인 기법으로 새로 작성했고 테스트 픽셀은 코드로 생성했습니다.

관련 자료: [모델 고지](mobile/assets/models/README.md), [모델 manifest](mobile/assets/models/manifest.json), [자료 사용·구현 기록](docs/vision-implementation-notes.md).

### 6.3 실시간 처리와 메모리 제한

| 항목 | 현재 구현 |
|---|---|
| 카메라 입력 목표 | 640×480; Android RGBA, iOS YUV |
| 분석 빈도 | 최소 200ms 간격, 최대 초당 5회 |
| 모델 추론 | 카메라 전용 네이티브 스레드에서 한 번에 1개 |
| 처리 중 새 프레임 | 네이티브에서 버림 |
| 실제 앱의 대기 영상 큐 | 두지 않음 |
| UI 전달 | 최대 25개 객체의 작은 메타데이터, 전달 대기 최대 1개 |
| 추적 기록 | 최대 12개 객체 × 최근 4개 관찰, 최대 3개 주의 후보; 일반 객체 표시는 최대 5개 |
| 결과 유효 시간 | 프레임 콜백 시작부터 1초, 미래 시각도 거부 |
| 자동 음성 | 최신 대기 발화 1개; 일반 주의 최소 4초·동일 주의 8초, 우선순위 상승은 별도 1.5초 제한으로 먼저 안내 |
| 원본 기록 | 파일·base64·영상 이력·서버 프레임 업로드 없음 |

성공·오류·스킵 모두 `finally`에서 변환 버퍼와 원본 프레임을 반환합니다. 모델이 버퍼를 읽는 중에는 먼저 해제하지 않습니다. 카메라를 닫으면 장치 입력·출력과 콜백을 분리하고, 모델·변환기·미리보기를 정리합니다.

반복 실행으로 스레드가 늘어나는 일을 줄이기 위해 프레임 출력·worklet·카메라 세션 한 세트를 앱 수명 동안 재사용합니다. 정리가 실패하면 재할당을 막고 재실행을 안내합니다. 이전 결과는 1초 뒤 지우고 앱 복귀 후 자동으로 카메라를 켜지 않습니다.

초당 5회는 상한이며 실기기 보장 속도가 아닙니다. 전체 앱 메모리에는 OS 카메라 풀·GPU·모델 메모리도 포함되므로 실제 측정이 필요합니다.

이전에 만든 [RealtimeFrameProcessor.mjs](mobile/vision/RealtimeFrameProcessor.mjs)는 ‘분석 중 1장 + 최신 대기 1장’ 구조의 별도 Y8 참조 모듈입니다. 현재 네이티브 앱의 ‘대기 영상 큐 없음’ 방식과 혼동하지 않도록 구분해 남겼습니다.

상세 설계: [실시간 카메라·메모리 문서](docs/realtime-camera.md).

### 6.4 별도 서버 사진 설명 모듈

- 이미지 파일 형식·용량·픽셀 수를 확인하고 EXIF/GPS를 제거합니다.
- 작은 해상도·어두움·과다 노출·세부 정보 부족이면 외부 모델을 호출하지 않고 재촬영을 안내합니다.
- 촬영마다 UUID를 보내고 최신 요청·응답 일치 여부를 검사합니다.
- 오래된 응답, 이동 재개, 화면 종료, 동의 철회 이후의 결과는 출력하지 않습니다.
- 임시 사진 정리 콜백을 필수로 받으며 성공·오류·취소 뒤 정리합니다. 삭제 실패 시 추가 촬영을 막습니다.
- 외부 전송 동의가 없으면 클라이언트에서 촬영/전송을 하지 않고 서버도 제공자를 호출하지 않습니다.
- HTTPS를 기본으로 요구하고 리디렉션 차단을 지원하는 `expo/fetch` 같은 구현을 명시적으로 주입합니다.
- 고불확실성 응답을 읽을 때 확실하게 알 수 없다는 문구를 덧붙입니다.

이 모듈은 현재 APK 화면과 미연결입니다. 실제 외부 AI 응답 품질·속도·요금과 네이티브 파일 삭제·네트워크 동작은 별도 검증이 필요합니다. 이미 외부로 전송된 사진을 동의 철회로 회수하는 기능은 아닙니다.

관련 파일: [LatestVisionController.mjs](mobile/vision/LatestVisionController.mjs), [createVisionTransport.mjs](mobile/vision/createVisionTransport.mjs), [연결 예제](mobile/vision/README.md).
